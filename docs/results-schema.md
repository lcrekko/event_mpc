# Saved-data dictionary

All simulated times are seconds; timestamps in detector/action records share
the run's simulation clock. CPU wall times are separate. Angles are mirror
angles in radians, not beam deflection. Figures convert angles to degrees.

## Full controller experiments (Milestone F)

Each configuration directory contains:

| File | Contents |
|---|---|
| metadata.json | Actual initial state, seed, search budget/method, plant/predictor parameters, solver tolerances, objective weights, software/source provenance, delay assumptions |
| trajectory.npz | `time` [samples], `state` [12,samples], full simulator truth and cumulative auxiliary integrals |
| events.json | Detector identities/timestamps; true crossing data for validation; reconstructed observation; pulse-switch timestamps; rejected pair reasons |
| actions.json | Applied theta, actual application time, estimated state, estimated crossing timestamp, selected cost, fallback flag and optimizer wall time |
| search.npz | All evaluated `sequences` [evaluations,N,3], `costs` [evaluations], integer `statuses` [evaluations] |
| search-index.json | For each event/round/evaluated mean, offset/count into the concatenated search arrays |
| status.json | Completion/failure status, completed/requested intervals, JIT warmup and total runtime, numerical status-code legend |
| metrics.json | Derived metrics from saved files, regenerated by report.py |

State rows in the full controller trajectory:

| Row | Quantity | Unit |
|---:|---|---|
| 0 | alpha | rad |
| 1 | omega | rad/s |
| 2,3,4 | neuron A fast/slow/ultraslow voltage | model voltage units |
| 5,6,7 | neuron B fast/slow/ultraslow voltage | model voltage units |
| 8 | accumulated integral abs(torque*omega), equation (19) | J |
| 9 | accumulated signed exact work, sine torque (2) | J |
| 10 | accumulated signed printed-(4) work, -kappa I² alpha omega | J |
| 11 | accumulated viscous dissipation | J |

Raw adaptive-node records can contain repeated boundary timestamps with equal
physical states when integration stops/restarts. Integrals in F remain cumulative
across intervals and pulse switches. Metrics use the true final crossing to
bound work for exactly K half-swings, excluding the final detector-delay tail.

Theta columns are `[I0 in A, slow gain, ultraslow gain]`. They do not specify
constant actual current: actual I(t)=I0 indicator(vf_A>=0). Both gains change
without resetting any neuron or mechanical state. The observation includes only
`crossing_time`, `available_time`, estimated `omega`, and detector order. Actions'
estimates come from those sensor records and known circuit history, not the true
state rows. `true_time`, `true_omega` and full trajectories are validation data.

Objective weights array order is `[T, A0, wA, w_tau, gamma]`. Costs are s²;
temperature 250ms² is .00025s². Invalid cost is stored as infinity in NPZ and
paired with a nonzero integer status; it is not a successful prediction.
Status code meanings are included in each status.json. JSON selected cost is
null for an all-invalid fallback. Mean candidates and newly evaluated means
appear in the same candidate arrays; the best valid evaluation is selected
across all of them. Original source hashes refer to code at run time.

## Earlier milestone artifacts

- A trajectory has five rows: alpha, omega, signed exact work, printed-(4) work,
  dissipation. Its separate metadata also lists the row names.
- B neuron trajectory has six voltage rows in A-then-B order, plus threshold
  events for each neuron, with no mechanical state.
- C uses the same twelve-row layout as F, but its demonstration resets auxiliary
  integrals between successive observation passages. All eight physical/circuit
  states remain continuous. Its purpose is sensor/actuator validation, not an
  accumulated-work controller experiment.
- D saves event-to-event output times, extrema, work and continuation states.
- E debug uses the F layout with a deliberately small M=8/K=3 budget. In E's
  historical generic provenance envelope the seed can be null even though the
  actual controller seed is stored at metadata's top level (seed1). F records
  the seed/RNG explicitly in both places; old metadata is not rewritten.

## Reading arrays on Windows

From the repository root:

```powershell
.\.venv\Scripts\python.exe -c "import numpy as np; d=np.load('results/milestone-f/nominal-seed1/trajectory.npz'); print(d.files); print(d['state'].shape)"
```

Use `python -m event_mpc.report --suite results/milestone-f` with the project
venv to regenerate CSV/JSON metrics and figures. This postprocessing performs
no ODE integration or controller optimization. The separate numerical_audit
command intentionally reintegrates frozen candidates to check convergence.
