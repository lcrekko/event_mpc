# 第一次使用这个项目

所有正式代码、说明、测试和已保存的实验结果都在 GitHub 的 `Solid_first`
分支。Codex 在云端运行代码；提交并推送之后，你的本地电脑仍需拉取一次，
本地文件才会更新。后续已要求 Codex 每完成一项工作就在该分支提交并推送。

## 在 GitHub 上看结果

- 根目录 `README.md`：安装与运行入口。
- `docs/onboarding/`：最初的论文审计、问题和计划，保留历史记录。
- `docs/milestones-b-f.md`：模型、控制器实现及数值验证的具体决定。
- `results/milestone-f/REPORT.md`：实验报告和图像。
- `results/milestone-f/summary.csv`：可用 Excel 打开的指标表。
- 每个实验子目录：配置、动作、探测器事件、轨迹和优化器全部候选。

结果表中的 `completed 50/50` 表示对应仿真完成了 50 个区间，不代表控制效果
一定良好，也不代表在真实硬件上可以实时计算。报告会单独列出误差、能量和耗时。
`unrun` 表示尚未运行；失败或提前终止也会保留，不能当成完整成功结果。

## 获取到 Windows 本地

如果已经克隆，在该项目的终端执行：

```powershell
git switch Solid_first
git pull origin Solid_first
```

如果还没有克隆：

```powershell
git clone --branch Solid_first https://github.com/lcrekko/event_mpc.git
cd event_mpc
```

## 配置 Python 和 VS Code

使用 Python 3.12，在仓库根目录执行：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

VS Code 中打开这个文件夹，安装 Python 扩展；按 Ctrl+Shift+P，选择
`Python: Select Interpreter`，然后选择 `.venv\Scripts\python.exe`。
以下命令显式指定了解释器，不需要先激活环境或修改 PowerShell 执行策略。

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
$env:NUMBA_NUM_THREADS="4"
.\.venv\Scripts\python.exe -m event_mpc.closed_loop --output outputs/my-first-run --intervals 3 --samples 8
```

第一次编译会较慢。小规模运行仅用于确认流程，不能替代论文规模的实验。
每次使用新的输出目录，旧结果不会被覆盖。项目目标是 Windows，但目前实际
运行和验证是在 Linux 云环境完成，Windows 尚未实机验证。

## 不重算仿真，直接重画图

从已下载的原始实验数据生成报告和图：

```powershell
.\.venv\Scripts\python.exe -m event_mpc.report --suite results/milestone-f
```

这只计算指标并绘图，不运行控制器优化。`trajectory.npz` 保存原始数值数组，
`metadata.json` 保存配置、软件版本和代码来源；`search.npz` 保存候选序列、
代价与有效性状态。原始元数据反映实际运行时的代码状态，不会在推送后伪造新版本号。

## 两个仍需区分的问题

论文式 (2) 的精确力矩被保留，式 (4) 和 PDF 没有修改。有限角度下两者的
能量平衡差异在结果中单列。控制器遵守第二个探测器事件之后才应用参数的因果
顺序；但目前只是测量优化耗时，没有把这段计算时间加入模拟控制延迟。因此
即使仿真完整结束，也不能据此声称真实系统可以实时执行。
